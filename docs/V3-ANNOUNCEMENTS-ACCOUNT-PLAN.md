本次重新执行 `node scripts/check_sync.cjs`，22 个模拟场景通过；这些不是线上 CloudBase 验收。

另用同一测试框架补做了双设备同时保存的诊断：

1. A、B 设备先读取同一账号备份。
2. A 修改转盘，B 修改昵称。
3. 两次读取同时完成，再分别执行原有 `doc(uid).set(payload)`。
4. 结果为 B 的新昵称保留，A 的新转盘恢复成旧云端转盘，两次写入均返回成功。

原因：`scripts/sync.js:105–120` 的“先读取、合并、再覆盖整份文档”不是原子操作。原有 22 项测试覆盖单设备和切换账号的竞态，但不覆盖这个双设备同时写入问题。需增加回归用例并修复，不能把现状报告为“所有配置已可靠跨设备同步”。

每 5 秒读取一次，在持续运行时每账号设备约 720 次/小时；无编辑时也读取包含头像的整份文档。v3.0 改为事件触发和低频前台复核。

## 3. 覆盖升级与会话恢复

已有有利条件：

- `com.randomtoolbox.app` 和固定证书不变，覆盖安装不会主动删除 App 数据。
- WebView 固定使用 `https://appassets.androidplatform.net/assets/index.html`，启用 DOM storage，未发现启动时清空 Cookie、WebStorage、SDK 凭据的代码。
- SDK 本身具有本地持久化支持，现有代码调用 `getSession()`，没有自己保存密码。

需要修复的代码问题：

- `rtStartAuth()` 在首次会话检查成功之后才注册 `onAuthStateChange`。8 秒超时或网络失败时会跳过注册。
- 网络错误与真实未登录目前都被设置为 `rtLoggedIn=false`，并调用账号切换逻辑；缓存仍可能存在，但界面会变成游客。
- `online` 与页面重新可见目前主要触发数据同步，未建立完整的认证恢复重试。UID 未恢复时同步自然不会启动。
- SDK 没有显式声明持久化策略，且 CI 依赖未锁定。

额外离线诊断直接提取现有认证脚本，模拟正常会话与超时：正常启动注册 1 个认证监听并进入登录态；超时启动注册 0 个监听并进入游客态。没有调用真实认证服务，也没有测试账号或凭据。

实施：显式沿用本地持久化；先订阅认证事件，再开始单次会话恢复；区分“恢复中、已验证登录、离线待验证、已退出/凭据确实失效”。短暂超时不调用 `signOut()`、不清 SDK 存储、不切换配置归属。联网、回前台及用户重试时合并触发一次恢复，过期响应不能影响新账号。尽量直接使用认证事件提供的会话，避免事件中重复刷新形成循环。

离线缓存身份只能用于本地展示和本地工具，不作为管理员、会员或云端写入的授权依据。无有效云端身份时不发起账号数据写入。显式退出仍清除 SDK 会话，保留分账号待上传缓存，不自动保存密码。

同签名覆盖升级的实际登录持续性还需真机验证，不能承诺过期、撤销或已注销的会话永远有效。卸载、清除数据会删除本机登录状态和未上传数据，不要求用户为本次功能卸载。

## 5. 新集合的完整字段设计

### announcements

一条公告一个文档；数据库不要求预建字段。下列是字段说明用的草稿样例，不需要现在导入生产数据：

```json
{
  "_id": "由服务器生成",
  "schema": 1,
  "title": "开心盒 v3.0 功能说明",
  "bodyText": "公告正文，由管理员填写。",
  "status": "draft",
  "priority": "normal",
  "contentRevision": 1,
  "createdAt": 0,
  "updatedAt": 0,
  "publishedAt": null,
  "createdBy": "服务器取得的管理员 UID",
  "updatedBy": "服务器取得的管理员 UID"
}
```

约束：

- `status` 仅 `draft`、`published`、`withdrawn`。不做定时发布，不增加定时触发器。
- `priority` 仅 `normal`、`important`。
- 标题 1～80 字符，正文 1～8,000 字符；请求限制 32KiB，拒绝额外控制字段与脚本内容执行。
- 所有时间由服务器产生，使用毫秒时间戳；客户端不能指定作者或发布时间。
- 新建草稿 revision 从 1 开始。已发布公告实质改动并确认重新发布时递增 revision，重新判定已读；普通草稿保存不反复触发通知。
- 发布和撤回采用预期 revision 的事务校验；重复点击和两端编辑不静默覆盖。撤回代替物理删除。
- 公开返回值仅包括 ID、标题、正文、优先级、revision、发布时间，不返回管理员 UID 和草稿。

### announcement_reads

按“账号 UID + 公告 ID”保存一条记录；修订复用该记录，不为每次打开追加流水：

```json
{
  "_id": "SHA-256(uid + 空字符分隔符 + announcementId) 的 64 位十六进制值",
  "schema": 1,
  "uid": "服务器认证得到的 UID",
  "announcementId": "公告 ID",
  "readRevision": 1,
  "readAt": 0
}
```

- 客户端只提交公告 ID 与实际展示过的 revision，UID、文档 ID、时间均由服务端生成。
- 服务端只允许标记已发布且真实存在的公告。若内容已更新，不能把用户没看过的新 revision 自动标为已读。
- 重复标记幂等，旧请求不能把 `readRevision` 降低；同一账号跨设备恢复已读。
- 离线先按 UID 排队，只有服务器确认后显示“已同步”；游客只存本机已读。账号切换隔离缓存，不用共享手机上其他账号的已读状态代替当前账号记录。
- 不提供普通用户批量查询他人已读、修改他人记录或删除整个已读集合的接口。

## 6. 权限、身份与函数接口

两个新集合都采用“仅云函数访问”。在 CloudBase 文档数据库的安全规则中，分别完整填写同样的内容：

```json
{
  "read": false,
  "write": false
}
```

这只适用于新建的 `announcements`、`announcement_reads`，不是整个环境的权限模板，**不要复制到现有 account_backups**。云函数服务端 SDK 通过运行角色访问数据库，因此云函数必须逐操作校验；不能把数据库拒绝客户端访问当成云函数无需鉴权的理由。

管理员身份：

1. 使用已有 CloudBase 真实账号登录。管理员名单配置在 `happyboxAnnouncements` 云函数环境变量 `HAPPYBOX_ANNOUNCEMENT_ADMIN_UIDS` 中，值为 UID 的 JSON 数组。UID 不是密码，但也不放进客户端判断权限。
2. 空/格式错误名单默认拒绝所有管理操作。未配置实际 UID 前不提供可用发布权限。
3. 仅从云函数平台提供的可信调用上下文取得 UID。服务端 SDK 支持 `auth().getAuthContext(context)` / `getCloudbaseContext(context).TCB_UUID`；调用方式需在当前环境测试确认。`context` 必须是函数运行时的参数，不得使用 `event.context`。没有可验证的真实用户身份直接拒绝管理和账号写入，绝不回退信任请求中的 UID。
4. 拒绝匿名用户；发布、编辑、撤回等每次都重新核对服务端名单。客户端 `role`、昵称、邮箱文本、localStorage 和管理页地址均不能授予权限。
5. 使用云函数运行角色的临时凭据，不填写 SecretId/SecretKey、不创建管理员万能密码、不把管理员令牌塞进 APK。
6. 不新增公开 HTTP 管理入口。通过现有 SDK `callFunction` 调用，预览不发布；不记录密码、会话 token、头像正文或整份用户备份。

`happyboxAnnouncements` 接口白名单：

| action | 允许身份 | 服务端限制 |
| --- | --- | --- |
| `list`、`detail` | 当前 SDK 允许的公开调用身份与已登录账号 | 只返回 published；参数白名单、单页最多 20 条。 |
| `readState`、`markRead` | 真实非匿名登录用户 | 只允许上下文 UID 本人；批量 ID 最多 20。 |
| `adminStatus` | 真实登录用户 | 只返回本人是否有管理权限，不泄露名单。 |
| `adminList`、`saveDraft`、`publish`、`withdraw` | 名单内真实登录用户 | 每次校验；草稿不公开；事务 revision/幂等校验。 |

现有 Publishable Key 的未登录函数调用能力需在控制台验收。若当前环境拒绝该类公开调用，游客先展示本地缓存并提示联网/登录后刷新；不自动开匿名登录、不修改认证策略、不把管理员函数改成无鉴权 HTTP。是否扩展游客首次联网读取在实际能力核实后确定，不能把未验证能力报告为完成。

## 7. 账号同步并发与旧版兼容方案

`happyboxAccountSync` 只接受真实 UID 本人，接口为 `pull`、`push`：

- `pull` 读取现有 `_id=UID` 的 schema:2 文档，返回配置及服务端计算的内容指纹 `etag`。不是用户 token，不具备授权能力。
- `push` 接受 `expectedEtag` 和白名单内的变更；数据库事务内再次读取同一文档，对比指纹后写入。
- 指纹不一致返回 `CONFLICT` 与最新本人配置，客户端三方合并未提交变更后重试，最多两次；再冲突保留本地并提示处理，不无限循环。
- 仍写 `{schema:2, values, updatedAt}`，不迁移或删除旧备份，不要求为旧文档补 revision 字段。指纹是当前服务器内容的摘要，不改变云端已有结构。
- 只允许现有四个偏好 key 和 `rt_profile_<调用者 UID>`。拒绝其他 UID、角色、会员、额度和账目等字段。保留旧文档中不属于本次补丁的合法存量字段，不整份删掉。
- 服务端校验选项数量、有效工具 ID、资料字段、头像类型与备份大小；昵称/头像按字段合并，不能用一个默认头像盖掉另一设备的新昵称。
- 内容版本/账号切换/请求超时继续沿用 generation 保护，云端写入成功后才能显示已同步；登录初次恢复期间的本机编辑仍需保留。
- 云函数未部署或权限不足时保留本机数据并显示失败，不悄悄回退到危险的整份覆盖写入。

旧版兼容限制必须保留在交付说明：2.9 客户端仍能走原直接 `.set()`，可能在 v3.0 写入之后覆盖文档。新函数的事务不能阻止一个未来的旧客户端覆盖写入。此阶段**不改现有 account_backups 权限**，保留旧版可用；验证和公告提示多设备使用同版。

只有在管理员确认旧客户端已退出使用、迁移和真实备份已验证后，才另行考虑将现有备份集合客户端写权限收紧为仅服务端。这需要单独 review 当前线上规则和兼容影响，不在本次自动执行。不能声称跨所有旧版客户端已彻底解决并发。

## 8. 资源与离线策略

- 公告：启动使用缓存；缓存过期（默认 15 分钟）再检查；列表手动刷新可强制检查；切回前台需经过节流。不使用实时监听、后台常驻、定时云函数或推送服务。
- 每次列表查询最多 20 条；重要公告单独取最近候选（最多 10 条），服务端合并去重后批量查询本人相关已读，避免按公告逐个请求。读写都设数量、大小和超时上限。
- 同步：登录恢复一次；本地编辑约 800ms 防抖；回前台/联网事件节流；无修改时仅前台每 15 分钟复核一次。移除 5 秒轮询，后台停止周期请求。
- 网络失败按 30 秒、2 分钟、5 分钟、15 分钟退避，后台不持续重试；手动操作可重试。调用去重、超时、旧响应丢弃。
- 头像先优化新增上传的压缩与大小提示，不新增云存储桶，不改存量照片格式，不触动现有动物素材。
- 预算核算看实际云函数调用和 DB 读写次数；一个云函数调用仍可能有多次数据库读取，并非零成本。发布前先查现有套餐和余额，不开通新套餐、常驻实例、自动扩容付费或新服务。
- 公告服务异常不影响随机工具或现有 APK 更新；认证离线不清除本地偏好。管理页无网络时不能宣称发布成功。

以下是目标配置，**不是要求现在立即操作生产环境**。当前先完成核对；源代码和部署包在实施阶段交付后再进行创建/部署。页面名称随控制台版本可能略有变化。

1. 手机浏览器访问腾讯云官方控制台，从“云开发 CloudBase”进入；需要时开启浏览器“桌面版网站”并横屏。

4. “数据库/文档型数据库”查看是否已有 `account_backups`，复制其**当前安全规则文本**供审查，并确认自己的 `_id=UID` 备份文档是否存在；无需提供完整私人资料或头像内容。

开发仍可在管理员 UID 未提供时继续，管理权限默认全拒绝；不能因此写入一个默认管理员账号。

### B. 实施完成后，新建集合和索引

1. 同一环境 → 文档型数据库 → 创建集合 `announcements`，再创建 `announcement_reads`。仅创建新集合，不覆盖同名已有数据；如已存在先核对。
2. 分别进入集合“权限设置/安全规则”，逐个填写第 6 节 `{ "read": false, "write": false }`，检查语法后保存。保持 `account_backups` 原规则不动。
3. 索引目标如下。若控制台提示套餐限制，不购买额外能力，先反馈并调整分页方案。

| 集合 | 索引名称 | 字段顺序 | 唯一 |
| --- | --- | --- | --- |
| announcements | `published_list` | `status` 升序、`publishedAt` 降序、`_id` 降序 | 否 |
| announcements | `important_list` | `status` 升序、`priority` 升序、`publishedAt` 降序、`_id` 降序 | 否 |

若控制台对组合 `_id` 有限制，实施时以当前引擎返回的索引建议验证并同步调整稳定游标；不猜测修改现有索引，不在手机上反复新增无用索引。
