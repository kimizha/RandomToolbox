# v3.0 双设备会话与设备管理补充方案

基线：`d8a2145`，`ui/android-happybox-redesign`。本文件补充原 `V3-ANNOUNCEMENTS-ACCOUNT-PLAN.md`，不替代原公告、schema:2 同步和认证恢复方案。按最终任务书，本轮只规划；确认后才开发，腾讯云配置由用户确认后执行，用户完成配置并确认后才构建测试 APK。

## 1. 安全边界与待验证能力

现有客户端使用 CloudBase JS SDK 3.x 的 `getSession`、认证事件和 `signOut`。检查了可取得的 SDK 类型/实现资料，尚未确认存在可用于本环境、按某个安装实例撤销底层 refresh/access token 的服务端接口。`signOut()` 不能被解释为可靠撤销另一台设备令牌。当前没有腾讯云管理身份，不能核实生产认证服务能力。

因此采用可信服务端管理的**应用级设备会话**。上线前须核实服务端可信 UID、匿名标志、事务、认证刷新与重新认证能力。应用级踢出不代表 CloudBase 底层令牌失效。凡 SDK 自身可直接调用的资料修改、数据库、存储及其他业务接口均须审查；不能声称撤销了整个 CloudBase 账号的所有访问能力。

完整强制限制依赖：所有受保护业务经云函数校验会话，且 `account_backups` 客户端读写通道已在获批后关闭。兼容阶段只保证接入新版云函数的业务，不保证旧版直写或底层认证接口。

## 2. 设备身份和凭据

- Android 首次使用 `SecureRandom` 生成安装 ID，保存在 App 私有 SharedPreferences；不读取 IMEI、序列号、广告 ID。不改既有 WebView origin；覆盖安装保留，卸载后可重新生成，沿用现有不自动备份的设置。
- 安装 ID、设备名称和手机/平板类型均不是授权证明。名称限制长度并安全转义，只用于展示，不上传精确硬件指纹、IP 或定位。
- 服务端在真实非匿名 CloudBase UID 下签发独立随机 256 位应用会话凭据；客户端私有存储保管，数据库仅存摘要，恒定时间校验，绝不记录完整凭据。凭据绑定 UID、会话 ID 和安装 ID；其他用户即使知道设备 ID 也不能操作。
- 每个受保护 RPC 必须同时具有 CloudBase 有效身份和对应应用会话凭据。不能仅凭设备 ID、客户端 UID、角色、邮箱、APK 版本字段或 LocalStorage 放行。
- 原生桥只允许可信内置来源访问凭据能力，外部页面用浏览器打开。电脑管理页面使用 HTTPS 同源私有客户端存储，不提供 URL token；其浏览器实例也占一个名额，不给管理员绕过设备限制。浏览器清站点数据可视为新实例；不承诺抵御已攻陷终端复制凭据。
- 安装凭据按 UID 隔离；切账号不复用其他账号 token。设备列表不返回其他设备的凭据或摘要。

## 3. device_sessions 数据结构

采用**每个 UID 一条协调文档**，不使用“先数设备、再插入设备”的竞态方案。文档 ID 由服务器从可信 UID 确定，例如 UID 的 SHA-256。示意如下，不导入生产：

```json
{
  "_id": "server-derived-account-key",
  "schema": 1,
  "uid": "server-authenticated-uid",
  "nextSequence": 4,
  "securityRevision": 7,
  "active": [
    {
      "sessionId": "server-random-id",
      "installationId": "random-install-id",
      "credentialHash": "server-computed-digest",
      "loginSequence": 2,
      "createdAt": 0,
      "lastActiveAt": 0,
      "expiresAt": 0,
      "deviceName": "我的平板",
      "deviceType": "tablet",
      "lastMutation": null
    }
  ],
  "recentRevocations": [],
  "admissionReceipts": [],
  "updatedAt": 0
}
```

`active` 始终最多 2 项；`loginSequence` 为事务内单调递增整数，以成功提交的次序为准，不按设备时间或最后活跃排序。并发提交无法以墙钟时间定义先后时，事务提交顺序就是确定的业务顺序。

撤销记录包含会话 ID、原因、撤销时间和必要展示信息，不含明文凭据。区分 `evicted_fifo`、`kicked_by_owner`、`signed_out`、`expired`。最近记录最多 20 条且最长保留 30 天；请求收据也严格限量和过期，避免协调文档无限增长。失效/未知会话都拒绝访问，旧撤销记录清理不会使会话复活。仅保存有限状态，不存完整登录行为日志。

默认有效期：连续 30 天没有经服务器确认的活动后过期；有效活动续期但不改变登录序号。被撤销的会话不可续期。普通重启、短暂断网和覆盖安装不会重新占位。过期清理在登录、验证、列表及业务事务中惰性执行，无定时清理服务。时间全部取服务器，不相信客户端时钟。

## 4. 云函数和共同校验

新增 `happyboxDevices`；保留已规划的 `happyboxAnnouncements`、`happyboxAccountSync`。共享鉴权、事务会话检查和错误码模块，打包到三个函数的部署包中，避免每次业务先远程调用设备函数再调用业务函数。

| 接口 | 条件与行为 |
| --- | --- |
| `register` | CloudBase 真实身份与有效准入证明；事务建立会话、分配顺序，必要时撤销最早会话。不能由后台心跳自动调用。 |
| `resume` / `validate` | 检查原会话凭据、归属和有效期，返回状态；不分配新序号。不存在/过期/被踢都不得静默 register。 |
| `list` | 当前有效会话；返回本账号最多两台活动设备及有限撤销状态，标记当前设备。 |
| `revoke` | 当前有效会话；目标必须属于同一 UID，事务撤销其他会话，操作前二次确认；不接受请求 UID 选账号。 |
| `logout` | 撤销当前应用会话后调用 SDK 退出；重复提交幂等，禁止删除 CloudBase 用户。 |

共同校验顺序：可信服务端 UID → 排除匿名 → 解析有界参数 → 事务读取该 UID 会话文档 → 摘要校验/过期检查 → 执行业务权限校验。管理员再核对服务端 UID 名单。校验失败不执行业务，错误返回不得泄露其他 UID 是否存在。

以下都需要有效会话：账号备份读写、账号已读查询/写入、管理员权限和全部管理操作、设备管理。公开公告列表/详情与 APK 更新例外：允许游客访问，只返回公开数据，不返回私人已读。

## 5. 原子事务、撤销与重试

注册事务读取并更新同一个账号协调文档：清理过期项 → 校验准入/去重 → 新登录获取序号 → 如超过两项，撤销序号最小项 → 同事务保存。事务冲突由数据库重试，创建首条文档的并发冲突也必须处理。三个并发登录最终只能保留两个成功会话。

**敏感操作不能只在事务外验证设备。** 同步提交、标记已读、发布/撤回、踢人均在同一数据库事务中读取并更新协调文档的 `securityRevision`，同时执行业务写入；保证与撤销事务竞争同一文档。这样：业务先提交则视为踢出前完成；撤销先提交则业务重试时拒绝。不能承诺撤回已提交的历史操作。

读操作同样服务端检查，不把长时间的本地“验证成功”缓存当权限。撤销之后已经发出的网络响应无法收回；设备切换后的旧响应由客户端 generation 丢弃。

登录、发布、转移会话和同步写入使用有界 requestId 与 payload 摘要收据。对同一 ID 不同内容拒绝；事务重复不会重复淘汰设备、增加序号或发布。注册响应丢失须能恢复同一凭据：客户端先在私有存储持久化高熵注册重试密钥，服务器仅存摘要，用它在短时收据窗口内恢复同一注册结果，或采用等效的临时加密收据；不把明文长期凭据存数据库。撤销后的旧注册请求只返回已撤销，不能复活会话。窗口到期需重新认证，不能无限重放。

## 6. 重新登录的真实性：必须验证的上线门槛

恢复原有效会话与重新登录分开：A 被踢后，`resume` 必须返回被踢，不能凭仍有效的 CloudBase token 自动重新入场挤掉 B。前端的 `explicitLogin=true` 或“点击了登录”不是可信证明。

开发阶段核实 CloudBase 是否提供可由服务器验证的近期重新认证时间、一次性认证结果或受验证挑战。如果有，将其绑定 UID、安装实例和单次准入挑战再消费；单纯刷新 access token 不能被视为重新输入凭据。若没有，需复用该环境认证服务可在服务端验证的一次性验证码/认证交换流程，不能自造验证码或只相信客户端登录成功回调。

**目前尚未证实上述能力在当前生产环境可用。** 如果只有普通有效 token，无法证明被踢设备上的用户确实重新认证，而非恶意客户端后台重注册。此时可实现服务端最多两会话及业务撤销，但不能宣称已防止旧 token 自动重新抢位；严格模式不得开放这种无证明的重新准入。核实失败时须单独报告并提交认证适配方案，不能默认降级为前端假限制，也不擅自新增短信付费服务。首次加入新版设备体系的既有会话采用明确迁移准入流程，不能借“迁移”永久绕过重新准入校验。

## 7. 客户端状态与未上传数据

认证和应用会话采用独立状态：`restoring`、`active`、`offline_pending`、`revoked`、`expired`、`signed_out`。先恢复 SDK，再 resume 已持久化应用会话；仅在明确准入完成后 register。覆盖升级保留安装 ID、会话凭据及 FIFO 序号；2.9 首次迁移 v3.0 才建立应用会话。

设备被踢时停止账号上传/下载、管理员操作和云端已读同步；取消后续队列，旧响应无效。先按 UID、安装实例、原会话 ID 保存待同步配置及基线快照，再退出账号模式。提示“账号已在其他设备登录”或“此设备已被移出”，附“未同步修改已保存在本机，重新登录后可处理”。游戏中延后提示但立刻停止受保护云操作；随机历史、账目、素材和本机配置不清除。

重新登录同 UID 后，先拉最新云端再三方合并隔离草稿；不同字段自动合并，同字段冲突展示“保留本机/使用云端”两份摘要，选择前不丢弃草稿、不默认覆盖。转盘/抽签数组作为一个冲突字段，昵称与头像分别按字段合并；图片冲突提供预览，不显示 base64。登录其他 UID 不上传原账号草稿。

主动退出与被踢分别显示状态。在线退出尽量提交同步并撤销会话后 SDK 退出；失败不虚报释放名额。离线退出保留最小待撤销队列：若 SDK 退出后无法再获得云端身份，不能声称已远程释放，待服务器 30 天到期或其他设备手动移除；也可在真正清除 SDK 凭据前明确提示网络失败并让用户选择本机退出。未上传数据保留。

设备管理入口为“设置 → 账号安全 → 登录设备管理”。显示 n/2、设备名称、类型、最近活跃、当前设备与状态，其他设备有“踢出”二次确认；只有服务器确认成功才更新为已移出。返回键、深色、小屏与平板适配沿用现有组件。

## 8. 低频验证与成本估算

登录注册/恢复、联网、回前台与云端敏感操作校验；同一时刻合并请求，前台复核节流，空闲 15 分钟复核一次，后台停止。不使用实时监听或秒级心跳。敏感写入在原业务事务中校验会话，不另增加一轮 RPC。最近活跃最多每 15 分钟记录一次，安全写入所需协调文档更新例外；不改变 FIFO 序号。

账号同步保留 etag 和字段补丁方案。同字段冲突须用户选择；默认拒绝覆盖。轻量复核尽量只读取投影后的 `updatedAt`/元数据并携带 etag；兼容阶段若旧客户端时间戳不可信，需定期完整内容校对。严格阶段所有写入经服务端后才能可靠利用轻量元数据避免重复返回头像。不能声称完整大头像文档完全没有数据库读取成本。

估算场景：每账号两台设备，每台每日前台 1 小时、冷启动 1 次、额外回前台 2 次、编辑 5 次。每台约 1 次恢复 + 最多 4 次空闲复核 + 最多 2 次前台复核 + 5 次保存，约 12 次受保护业务 RPC/天；合并可减少。加公告缓存检查、阅读和偶尔设备列表，约 15～25 次/设备/天，即 30～50 次/账号/天，1000 个同等活跃账号约 3万～5万次/天。该估算不含 CloudBase 自身 token 刷新、认证验证码、故障重试和突发编辑，不是费用承诺。

普通事务约读取协调文档及业务文档并写必要文档，冲突重试会增加次数；公告候选和已读是批量查询。正式部署前按当前套餐单价、免费额度及实际计量试算，不自动购买服务。请求与文档设大小上限、用户级写入节流和分页；不以 IP 作为设备身份。

## 9. 数据库规则与迁移

新增 `device_sessions`，与两个新公告集合一样客户端规则为：

```json
{
  "read": false,
  "write": false
}
```

协调文档按确定性主键查询，无需为列设备新建用户扫描索引。保留公告原索引；同步仍按现有备份主键，不重建旧数据。运行角色具有必要集合权限，每个函数通过共享服务端检查模块限制其实际操作。

| 阶段 | 生产行为与边界 |
| --- | --- |
| 准备 | 导出当前 account_backups 安全规则，确认现有数据、额度、SDK 可信身份和事务能力；只读备份，不清空数据。 |
| 部署服务 | 用户确认后部署 device_sessions 规则、happyboxDevices、共享校验与另外两个函数；先以测试账号验证，旧备份规则不变。 |
| 兼容试运行 | 经用户完成云端配置并确认后才构建 v3.0 测试 APK；新版接口执行设备限制，旧版仍直写。明确标记“兼容阶段，未封闭旧通道”，不得宣称完整强制限制。 |
| 迁移确认 | 核验账号备份、同签名覆盖、三设备并发、旧客户端实际权限；管理员明确批准切换时点，先保存原规则与回退包。 |
| 严格切换 | 仅经批准将 account_backups 客户端读、写都拒绝，全部通过已验证会话的云函数。只封写会留下被踢设备读取私人备份的通道。此操作不删数据，但会使旧版同步失败，必须提前告知升级路径。 |
| 验收 | 验证旧 SDK 直读/直写拒绝；被踢设备即使 CloudBase token 仍有效，也不能操作私人业务或管理端；在线/离线和回退场景验收后才可称新版业务设备限制完整。 |

严格切换时新设备函数只需现有账号备份数据，不要求重建 schema。服务端验证的最低客户端协议版本可以拒绝旧 RPC，但客户端传来的版本号不能证明 APK 真实版本，也不能替代规则封闭。真正要求旧用户升级如需 APK 最低支持版本，另经确认并先有真实下载链接；当前 `version.json` 保持原状、空链接、forceUpdate=false。

紧急回退优先恢复上一套**仍校验设备会话**的函数版本，必要时暂停受保护写入但保留离线工具。若要恢复旧客户端直接读写，必须另经确认原样恢复事先导出的安全规则，同时明确完整设备限制与并发保证暂停；不能一边开放旧通道一边声称安全保证仍在。绝不设置公开读写、不清空 device_sessions、不回滚用户备份内容、不启用强制更新。

## 10. 与既有方案对齐的补充

- 公告新增独立 `popupEnabled` 布尔字段，重要程度与是否弹窗分别设置；每次启动主动弹窗最多一条。仅成功联网确认仍已发布的公告可主动弹，离线缓存仅供手动查看，避免已撤回公告离线误弹。首页提供入口和未读标记，读写仍按第 4 节会话边界执行。
- 游客必须能看公开公告：优先核实 Publishable Key 的公开函数调用；若不支持，交付与管理员接口分离的只读公开 HTTPS 适配入口，服务端仅允许公开 list/detail、限量缓存与参数校验，不开放管理动作或自动开启匿名认证。该入口的实际可用性、域名和已有套餐费用需用户确认后配置；不能以“游客必须登录”替代目标。
- 管理后台独立页面支持手机/电脑；电脑首次使用同样建立会话并计入两个名额。服务端名单 + 有效设备会话缺一不可。网页托管优先既有资源；当前未核实已有电脑端托管地址，不擅自购买。
- 常用仍最多一个；保留旧数组及顺序，读时取首项，用户主动换常用才写单项。多常用/排序若以后恢复需单独确认，本轮不实现。
- APK 更新优先于所有公告与账号提示；保留 v2.9 原生机制和实际 APK code。不得在本轮规划提交触发 APK 构建。
