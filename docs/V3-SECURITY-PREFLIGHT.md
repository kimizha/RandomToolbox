用户已批准手动部署只读探针；部署包、依赖加固和最新 19 项核验测试请见 [手机部署与安全报告](SECURITY-PROBE-MOBILE.md)。下文待授权描述为此前记录，不再需要重复申请同一部署许可。

本轮按用户要求先检查安全前提。当前分支 `ui/android-happybox-redesign`，起点 `8cad11a`。尚未部署或连接真实腾讯云环境，未修改现有 App 业务、备份、规则、版本配置或签名，也未构建 APK。

## 已确认与未确认

- SDK 资料提供可信运行时 UID、匿名标志和数据库事务 API；API 存在不代表当前生产环境已验证可用。
- 当前执行环境没有腾讯云管理身份、密钥绑定或管理工具。生产 IAM、事务运行与认证能力无法在本会话核实。
- 尚未确认该环境提供可供服务端验证的近期重新认证证明、一次性认证交换结果，或按设备撤销底层令牌的接口。不能把前端登录回调、刷新 token 或 explicitLogin 标志当作重新准入证明。
- 旧版 `scripts/sync.js` 仍直接访问 account_backups；按要求不关闭该通道。因此不能保证被踢旧客户端停止直接读写，也不能声称完整两设备限制。

依据用户“如果无法安全实现，停止相关功能”要求，暂停设备准入、自动挤出、手动踢出与管理界面接入，不启用不安全降级。也没有伪造一份可用设备列表。现有账号与工具继续保持原行为；不能说当前已具备踢出保护。

## 已准备的可审查代码

`cloudfunctions/happyboxSecurityProbe/` 为独立只读前置核验函数，入口 `index.main`，固定现有环境，不创建环境。固定依赖和锁文件，不内置 SecretId、SecretKey 或管理员名单。

仅通过可信运行时上下文验证 UID、非匿名身份和环境匹配，然后尝试在事务内读取本人现有 account_backups 文档。忽略请求内 UID/角色/context，不写数据库，不返回备份内容、不打印日志或凭据。返回本人的 UID 和能力状态；读失败不伪报成功。缺失备份、角色权限或事务错误均可能使读取未验证，不应据此直接认定数据库不支持事务。

`transactionReadVerified=true` 仅代表该次事务读取完成，不证明并发写入或重新认证安全。`concurrentWritesVerified`、`freshReauthenticationVerified` 和 `perDeviceProviderRevocationVerified` 当前始终为 false，明确表示尚未验证。

## 测试结果

- `node scripts/check_security_probe.cjs`：11 项离线模拟通过，包括真实上下文形状、匿名/缺失身份拒绝、UID 冲突、错误环境、失败读取、请求伪造及敏感内容不回传。
- `node scripts/check_sync.cjs`：原有 22 项同步模拟通过。
- 没有执行三设备真实登录、覆盖安装、云端并发事务或真实踢出测试；当前也未实现这些功能。模拟不能代替真实环境验收。
