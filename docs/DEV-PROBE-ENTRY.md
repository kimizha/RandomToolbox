## 测试入口隔离方式

- 实现在 `scripts/dev-security-probe.js`，不放入 Android 默认 assets。
- `inject_auth.py` 仅在明确设置 `HAPPYBOX_SECURITY_PROBE_TEST=1` 时注入，默认构建完全没有入口脚本和 UI。
- 注入后仍需 Android 原生确认该 APK 为 debuggable；普通浏览器或 release 运行时不显示。
- release 任务发现已注入测试脚本会中止，要求恢复干净源码重新生成；不会静默把测试入口打包进 release。
- UI Release 发布脚本检查实际 APK 内标记与验证报告，即使修改报告试图隐藏标记也拒绝发布。现有工作流不默认启用开关。本次提交使用 skip ci，不触发 APK 构建。
- 原有登录、同步、用户数据及 APK 更新配置不变。探针不会注册会话、踢人、写资料或变更登录状态。原同步仍按现有逻辑运行，因此登录期间原同步可能正常读写本人账号备份；不能把“探针只读”说成整个 App 停止现有同步。

## 以后获准构建后的真机步骤

本次不构建或分发 APK。后续另经允许，用干净 UI 分支源码生成账号界面，临时设置 `HAPPYBOX_SECURITY_PROBE_TEST=1` 执行原有注入流程，再只构建 debug 测试变体并沿用固定签名。测试包不可用于 Release 发布；正式构建用干净源码且不设置此变量。不能把已注入文件直接重用于正式构建。

1. 先完成上述线上版本核对。安全名单只保留获准测试账号；不因测试失败改数据库规则或添加客户端伪造身份。
2. 以后安装经批准、固定签名且 code 递增的测试包，直接覆盖安装，不卸载。通过原有登录界面使用真实测试账号登录，不向探针填写 UID、密码或 token。
3. 设置页底部会出现“开发测试 · 只读安全核验”。勾选“已核对线上代码”只用于记录测试者操作前提，不是服务器身份认证，不授予权限，也不意味着客户端已经自动核实云端版本。
4. 点击“使用当前真实会话核验”。先从现有 SDK 读取实际 session，再用同一实例 `rtCloudApp.callFunction({name:'happyboxSecurityProbe',data:{}})`；没有测试 UID 请求参数，也不新建认证客户端或登录令牌。
5. 页面只展示允许的状态字段与本人 UID，不打印原始响应、token、密钥、照片或备份。与账号管理里本人 UID 核对；对外反馈可遮盖 UID。
6. 快速重复点击只发一个请求；10 秒超时后可手动重试，无轮询。退出或切换账号后到达的旧结果丢弃。游戏页不会主动弹出本入口。

## 如何判断

- **真实身份核验成功**：服务端 `identityVerified=true`，UID 与实际 SDK 会话及本人控制台 UID 一致，环境为既有环境。客户端只显示筛选后的结果，不能替代服务端检查。
- **本次事务读取成功**：`transactionReadVerified=true` 且 `READ_PREFLIGHT_COMPLETE`。仅表示一次只读事务返回有效响应，不证明备份一定存在、写权限或并发一致性。
- **PROBE_NOT_AUTHORIZED**：查看服务端测试名单是否包含当前真实 UID，并先确认部署版本。不是客户端可绕过的开关，不修改前端来伪造成功。
- **REAL_USER_REQUIRED / TRUSTED_IDENTITY_UNAVAILABLE**：平台身份不满足要求；不能向请求里加 UID 来绕过。
- **读取未核实**：可能是数据不存在的返回方式、IAM、网络或 SDK 兼容性；不要立刻放宽数据库规则。
- **重新认证证明、并发写入和底层设备令牌撤销**：继续显示未核实。本函数从未核实这些能力，不能将 true 的普通身份状态当作“刚刚重新登录”的证据。

测试后关闭应用即可，不保存探针响应或身份到新的 LocalStorage 项。恢复普通无开关构建时没有临时入口。无需清用户数据或撤销现有同步权限。
